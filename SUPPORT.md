# Suporte

## Como obter ajuda

| Tipo de demanda | Canal |
|---|---|
| Bug em produção / incidente | `#incidentes` (Slack interno) + abrir issue no repo afetado |
| Dúvida técnica de desenvolvimento | Discussão no PR ou `#engenharia` (Slack interno) |
| Solicitação de feature | Issue com template `feature_request` no repo apropriado |
| Reporte de vulnerabilidade de segurança | **NÃO abrir issue pública.** Ver [SECURITY.md](./SECURITY.md) |
| Pergunta sobre integração de parceiro | Time de Integrações via `#integracoes` |
| Acesso a recursos / credenciais | `#devops` |

## Tempo de resposta esperado

| Severidade | Tempo de resposta inicial |
|---|---|
| Incidente em produção (P0) | Imediato (oncall) |
| Bug crítico (P1) | Até 1 dia útil |
| Bug normal (P2) | Até 3 dias úteis |
| Feature request / dúvida | Best effort |

## Antes de pedir ajuda

- Verifique se o repositório tem `README.md` ou `docs/` com a resposta
- Procure issues abertas/fechadas no GitHub
- Para incidentes: confira os dashboards (Grafana / CloudWatch) antes de escalar

## Horário comercial

Time de engenharia: **seg-sex, 09:00–18:00 BRT**. Fora desse horário, apenas incidentes P0 escalam para oncall.
